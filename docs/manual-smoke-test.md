# Browser AI MVP 手工冒烟测试

> 最后更新：2026-08-05  
> 目标浏览器：Chrome 114+，Manifest V3  
> 构建目录：`.output/chrome-mv3`

本文档用于发布前人工验证。自动化测试不能可靠覆盖 Chrome 权限弹窗、Side Panel、扩展 Service Worker 重启和真实网页选区，因此这些项目必须在干净 Chrome 配置中执行并记录结果。

## 1. 准备工作

1. 在项目根目录运行：

   ```bash
   npm ci
   npm run prepare
   npm run check
   npm run zip
   ```

2. 创建一个新的 Chrome 配置文件，打开 `chrome://extensions`，开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择 `.output/chrome-mv3`。
4. 固定工具栏中的 **Browser AI** 图标。
5. 准备以下页面：
   - 静态文章页；
   - 内容复杂的 Dashboard 或 SPA；
   - 包含文本输入框的普通页面；
   - `chrome://settings`；
   - Chrome Web Store 页面。
6. 准备一个支持 OpenAI Chat Completions 流式响应的测试 Gateway：
   - `POST {baseURL}/chat/completions`；
   - 接受 Bearer API Key；
   - 返回 OpenAI-compatible SSE chunk；
   - 最终 chunk 带 `finish_reason`。
7. 在 DevTools 中分别准备查看：
   - Side Panel 控制台与 Network；
   - `chrome://extensions` → 扩展详情 → Service Worker 控制台；
   - Application → Extension Storage。

> 测试 API Key 只使用临时凭证。不要在截图、Issue 或共享日志中保留真实密钥。

## 2. 基线检查

### 2.1 生成 Manifest

打开 `.output/chrome-mv3/manifest.json`，确认：

- `manifest_version` 为 `3`；
- `minimum_chrome_version` 为 `114`；
- 必需权限仅包含：
  - `activeTab`
  - `scripting`
  - `storage`
  - `sidePanel`
  - `contextMenus`
  - `alarms`
  - `unlimitedStorage`
  - `favicon`（仅用于显示 @ 标签页的网站图标，不产生安装提示）
- `optional_permissions` 仅包含 `tabs`（首次使用 @ 时与全部网站访问权限一起申请，之后不再弹窗）；
- `optional_host_permissions` 为 `http://*/*` 和 `https://*/*`；
- 没有静态 `<all_urls>` Content Script；
- 没有远程脚本或用户 API Key 构建变量。

预期：Gateway 的具体 origin 及全站访问都在运行时按需授权。

### 2.2 扩展图标与基础视觉

确认工具栏、Side Panel、设置页及 `chrome://extensions` 中显示扩展图标。检查 16、32、48、96、128 像素版本清楚可辨，没有裁边、锯齿异常或透明底色错误。

## 3. 十个 MVP 验收场景

每项记录：日期、Chrome 版本、Gateway、结果（通过/失败/受阻）和证据说明。

### 场景 1：首次配置与精确 Gateway 授权

1. 打开扩展“选项”。
2. 填写 Gateway 名称、HTTPS Base URL、模型和临时 API Key。
3. 点击“拉取模型”，接受 Chrome 的 origin 权限弹窗，并从返回结果中选择模型（也验证可手动输入模型 ID）。
   - 点模型输入框右侧箭头（或在输入框里按 ↓），确认弹出带“搜索模型”的面板且搜索框自动聚焦；输入关键字可按名称过滤（不区分大小写），无结果时显示“没有匹配的模型”；当前模型为主题色并带勾；↑/↓ + Enter 可选择；Esc 或点面板外关闭面板，Esc 不会影响页面其他部分。
4. 点击“测试网关”，确认显示连接成功和延迟。
5. 点击“保存配置”。
6. 检查权限弹窗只包含该 Gateway 的精确 origin，而不是所有网站。

预期：

- 拉取模型、测试和保存都复用当前 Gateway 的精确 origin 授权；
- 连接测试显示成功和延迟，且测试不会隐式保存草稿；
- 保存配置后重新打开设置仍能读到配置；
- API Key 输入不会在重新打开设置时以明文回填；
- 用户拒绝权限时不保存配置，并显示“需要授权”的恢复提示；
- HTTP Gateway 显示明文传输警告，并要求再次确认。

### 场景 1a：侧边栏一键快速配置

1. 移除已保存的 API Key（或使用全新的 Chrome Profile），打开侧边栏。
2. 确认顶部显示“连接 AI Gateway”卡片：接口格式切换（OpenAI 兼容 / Anthropic Messages）、Base URL、API Key、“更多设置”和“一键连接”。
3. 切换到“Anthropic Messages”，确认 Base URL 从 `https://api.openai.com/v1` 自动变为 `https://api.anthropic.com`（已手动改过的地址不会被覆盖）。
4. 不填 API Key 点“一键连接”，确认提示“请填写 API Key。”；填写 `http://` 远程地址时出现 HTTP 风险确认勾选框，未勾选不能提交。
5. 填写真实 Gateway 地址和临时 API Key，点“一键连接”：确认弹出 Chrome 的精确 origin 授权；拒绝授权时卡片保留并显示“需要授权”。
6. 允许授权后，确认按钮变为“连接中…”，完成后卡片消失；输入框右侧的模型为模型列表中第一个 Claude / GPT / Gemini 文本模型（跳过 embedding、语音、图片等模型；都没有时选第一个文本模型）。
7. 打开设置页“模型”，确认已保存一份名称为 Gateway 主机名的配置，模型与侧边栏一致。
8. 用一个不返回模型的 Gateway 重试，确认卡片提示“Gateway 没有返回可用模型，请在设置中手动填写模型。”，且不会保存配置。
9. 点“更多设置”，确认打开设置页并选中“模型”。

### 场景 1b：切换为 Anthropic Messages 接口格式

1. 在“选项”中把“接口格式”切换为“Anthropic Messages”，确认 Base URL 默认值变为 `https://api.anthropic.com`（若已填写自定义 URL 则保持不变）。
2. 填写 Anthropic 或兼容 Gateway 的临时 API Key 和模型（例如 `claude-opus-5-5`），点击“拉取模型”和“测试网关”。
3. 保存后在 Side Panel 发起一次带当前页和图片附件的提问。

预期：

- 请求发往 `<Base URL>/v1/messages`（Base URL 末尾的 `/v1` 会被自动去掉，不会出现 `/v1/v1`），流式输出正常，取消按钮可中断；
- 自定义请求头中不能覆盖 `x-api-key`；
- 不填“最大输出 Tokens”时按 8192 发送，Temperature 超过 1 时按 1 发送；
- 切回“OpenAI 兼容”后保存，原有 Chat Completions 流程不受影响。

### 场景 2：工具栏打开 Side Panel，页面仅在本地准备

1. 打开静态文章页。
2. 清空 Side Panel Network 记录和 Gateway 访问日志。
3. 点击扩展工具栏图标。

预期：

- Side Panel 在当前标签页打开；
- 用户手势触发 `activeTab` Content Script 注入；
- 输入框上方出现“正在分享“页面标题”标签页”上下文卡片，右侧有关闭按钮；
- 用户发送消息前，Gateway 没有网络请求；
- 页面正文和选区未写入 `storage.local`。

### 场景 3：带当前页的流式问答

1. 保留输入框上方的当前页上下文卡片。
2. 输入 `总结当前页面` 并发送。
3. 观察 Network、回答区域和停止按钮。

预期：

- 请求由 Background 发往已授权 Gateway；
- 回答逐步出现，而不是完成后一次性出现；
- 完成后停止按钮恢复为发送按钮；
- 最终对话持久化，刷新 Side Panel 后仍可见；
- 消息来源只保存页面标题、URL、上下文类型和截断标记，不保存完整正文。

### 场景 4：移除当前页后进行纯聊天

1. 点击当前页上下文卡片右侧的关闭按钮（“移除当前页上下文”），确认卡片消失并出现“分享当前页”按钮。
2. 输入一个容易在页面正文中定位的提问并发送。
3. 检查 Gateway 请求体。

预期：请求包含用户问题和对话历史，但不包含页面标题、正文或选区文本。

### 场景 5：选区快捷入口

1. 在文章页拖选一段文本，避开输入框和可编辑区域。
2. 点击浮动的“问 AI”，确认侧边栏打开并带入所选文本。页面右键菜单入口目前已停用。

预期：

- Side Panel 打开；
- 显示“选中文本”chip；
- 若“当前页”仍启用，请求包含选区及当前页；移除当前页后只包含选区；
- 输入框、`textarea`、`contenteditable` 内不出现干扰输入的浮动按钮；
- 按钮可点击、不被宿主 CSS 破坏、不超出视口。

### 场景 6：两个标签页独立对话

1. 在标签页 A 发起对话并获得回答。
2. 切到标签页 B，打开扩展并发起不同对话。
3. 在 A、B 间来回切换。

预期：每个标签页恢复自己的 active conversation、消息和上下文；任何请求都不会自动引用另一个标签页的页面内容。

### 场景 7：导航使旧上下文失效

1. 在 SPA 中打开 Side Panel，记下“当前页”内容状态。
2. 使用站内导航或 History API 跳转到新页面。
3. 发送下一条带页面上下文的问题。

预期：旧 snapshot 被失效；新请求使用新 URL 和新页面提取结果。若提取失败，UI 明确进入 chat-only 状态，不静默复用旧正文。

### 场景 8：取消响应并保留取消状态

1. 发起一个较长回答。
2. 收到部分 token 后点击“停止”。

预期：

- AbortSignal 中止请求；
- 已显示的部分回答保留，并有可识别的“已取消”状态；
- 不再追加 token；
- 用户可以继续提问或重试。

### 场景 9：保留周期、固定与清理

1. 创建普通对话与固定对话。
2. 使用测试数据或调整系统测试时钟，使两者 `updatedAt` 早于 30 天。
3. 触发启动、打开历史或每日 alarm 清理。
4. 测试“从不保留”、7、30、90 天和永久。

预期：过期普通对话删除；固定对话保留。缩短周期前显示受影响数量并要求确认；取消确认不修改设置或数据；“清除”默认不删除固定对话。

### 场景 10：Secret、页面内容与信任边界

1. 在 Service Worker、Side Panel 和页面 DevTools 控制台检查日志。
2. 搜索 API Key、`Authorization`、完整页面正文、完整选区和完整消息。
3. 从页面/Content Script 尝试发送伪造的 `GET_PROVIDER_SECRET` 消息。
4. 检查页面脚本能否访问扩展的 `storage.local`。

预期：

- 生产日志不包含 API Key、Authorization、自定义 header 值、完整正文或选区；
- 不存在读取 Secret 的 runtime/content route；
- `storage.local` 访问级别限制为 trusted contexts；
- Content Script 只能执行上下文提取、选区按钮控制和有限页面事件。

## 4. 权限与页面访问专项

### 4.1 默认 activeTab 模式

- 未点击扩展前，普通页面没有常驻 Content Script。
- 点击工具栏后仅当前标签页获得临时读取能力。
- 刷新或导航后需要新的有效用户手势，除非已开启全站模式。

### 4.2 全站自动访问模式

1. 在设置中选择“在所有网站自动可用”。
2. 接受 `http://*/*` 与 `https://*/*` 可选权限。
3. 在 `chrome://extensions` 的 Service Worker 控制台检查注册脚本。
4. 关闭全站模式，分别测试保留和移除 broad host permission。

预期：

- 只有用户确认后才保存 `all-sites`；
- 动态 Content Script 只注册一次；
- 关闭后 unregister；
- 勾选移除权限时 broad host permission 被移除；
- 拒绝权限时保持默认 activeTab 模式。

### 4.3 排除网站与仅本次允许

1. 添加 `example.com` 和 `*.internal.example.com` 到排除列表。
2. 打开匹配页面并通过工具栏手动打开 Side Panel。
3. 点击“允许本次读取”。
4. 重启 Service Worker 后再试。

预期：

- 被排除页面不自动提取，也不显示选区按钮；
- Side Panel 解释排除原因；
- 只有用户确认后本次读取成功；
- one-time token 不跨 Service Worker 重启持久化；
- 排除列表不会假装动态收回已授予的 broad host permission。

### 4.4 受限页面

在 `chrome://settings`、Chrome Web Store、扩展页等页面点击扩展。

预期：Side Panel 可以给出 chat-only/不支持说明；不抛出未处理异常；不能通过“允许本次读取”绕过 Chrome 限制。

## 5. Gateway 错误与恢复

逐项模拟并确认 UI 显示安全、可操作的中文提示：

- 配置缺失：`CONFIG_MISSING`；
- API Key 缺失：`API_KEY_MISSING`；
- Gateway host permission 缺失：`HOST_PERMISSION_REQUIRED`；
- 401/403：`AUTHENTICATION_FAILED`；
- 404 model not found：`MODEL_NOT_FOUND`；
- 429：`RATE_LIMITED`；
- 超时：`REQUEST_TIMEOUT`；
- 5xx/网络错误：`GATEWAY_UNAVAILABLE`；
- malformed chunk：`STREAM_PROTOCOL_ERROR`。

预期：错误提示不回显 Secret、响应正文或自定义 header；可重试错误提供清晰恢复路径。

## 6. Service Worker 中断

1. 发起长流式响应。
2. 在 `chrome://extensions` 点击扩展 Service Worker 的“停止”，或触发其重启。
3. 重新打开 Side Panel；等待启动 reconciliation。

预期：不承诺断点续传。超过阈值的 `streaming` assistant message 被标记为 `STREAM_INTERRUPTED`，提示后台重启导致中断并允许重试。

## 7. 视觉与无障碍 QA

在 280、320、360、420 像素 Side Panel 宽度检查：

- 顶部品牌、历史和新建按钮层级清晰；
- 对话区独立滚动，Composer 固定在底部且不遮挡消息；
- 触控目标通常不小于 44×44 px；
- 所有图标按钮有 accessible name；
- Tab 键顺序可预测，焦点环明显；
- 正常正文对比度至少 4.5:1；
- 错误、取消、上下文状态不只依赖颜色；
- 长中文、长英文 URL、表格和代码块不产生页面级横向滚动；
- Markdown 原始 HTML、`javascript:`、`chrome-extension:` 链接和远程图片不能执行或加载；
- `prefers-reduced-motion` 下动画被显著减少；
- 亮色/暗色 Chrome 工具栏环境中面板边界仍清晰；
- 空态、加载、流式、失败、取消、配置缺失、页面排除和受限页面状态均检查。

## 9. 当前自动化证据与人工限制

截至 2026-08-05，Task 17 的集成验证已实际运行：13 个 integration test files、43 个 tests 通过，TypeScript、ESLint 和 WXT production build 通过。

当前 Codex 环境未连接可控制的外部 Chrome；内置浏览器也会阻止直接加载扩展页面。因此本文件不把 Chrome 权限弹窗、真实 Side Panel、真实 Service Worker 重启和视觉截图标记为“已通过”。这些项目必须在可加载 unpacked extension 的 Chrome 中按上表执行。

## 浮动聊天（页面内）

1. 在普通网页上打开侧边栏，点「更多操作 → 浮动显示」。首次在该网站使用时，Chrome 会弹出网站访问授权，允许后：
   - 聊天面板出现在当前网页右下角；
   - 侧边栏自动关闭。
2. 拖动标题栏移动面板，拖动右下角调整大小；点「最小化」只保留标题栏，再点「还原」恢复。
3. 在面板中发送一条消息，确认流式回答正常。
4. 刷新页面，确认面板自动重新出现，位置和大小保持不变。
5. 切换到其他标签页，确认那里没有面板；切回来面板仍在。
6. 点工具栏图标打开侧边栏，确认面板从网页上消失。
7. 再次打开浮动面板，点面板右上角的关闭按钮，确认面板消失且侧边栏不会自动打开；刷新页面后面板也不再出现。
8. 在面板「更多操作」里点「在侧边栏中打开」，确认侧边栏打开、面板消失。
9. 在 `chrome://` 页面、新标签页或 Chrome 应用商店点「浮动显示」，确认侧边栏提示「当前页面不支持浮动显示」并保持打开。
10. 未配置 Gateway 时，在面板中点「一键连接」，确认不再出现 “This function must be called during a user gesture”。

### 场景 9：保留周期、固定与清理

1. 创建普通对话与固定对话。
2. 使用测试数据或调整系统测试时钟，使两者 `updatedAt` 早于 30 天。
3. 触发启动、打开历史或每日 alarm 清理。
4. 测试“从不保留”、7、30、90 天和永久。

1. 在 Service Worker、Side Panel 和页面 DevTools 控制台检查日志。

## 4. 权限与页面访问专项

### 4.1 默认 activeTab 模式

- 未点击扩展前，普通页面没有常驻 Content Script。
- 点击工具栏后仅当前标签页获得临时读取能力。
- 刷新或导航后需要新的有效用户手势，除非已开启全站模式。

### 4.2 全站自动访问模式

1. 在设置中选择“在所有网站自动可用”。
2. 接受 `http://*/*` 与 `https://*/*` 可选权限。
3. 在 `chrome://extensions` 的 Service Worker 控制台检查注册脚本。
4. 关闭全站模式，分别测试保留和移除 broad host permission。

预期：

- 只有用户确认后才保存 `all-sites`；
- 动态 Content Script 只注册一次；
- 关闭后 unregister；
- 勾选移除权限时 broad host permission 被移除；
- 拒绝权限时保持默认 activeTab 模式。

### 4.3 排除网站与仅本次允许

1. 添加 `example.com` 和 `*.internal.example.com` 到排除列表。
2. 打开匹配页面并通过工具栏手动打开 Side Panel。
3. 点击“允许本次读取”。
4. 重启 Service Worker 后再试。

预期：

- 被排除页面不自动提取，也不显示选区按钮；
- Side Panel 解释排除原因；
- 只有用户确认后本次读取成功；
- one-time token 不跨 Service Worker 重启持久化；
- 排除列表不会假装动态收回已授予的 broad host permission。

### 4.4 受限页面

在 `chrome://settings`、Chrome Web Store、扩展页等页面点击扩展。

预期：Side Panel 可以给出 chat-only/不支持说明；不抛出未处理异常；不能通过“允许本次读取”绕过 Chrome 限制。

## 5. Gateway 错误与恢复

逐项模拟并确认 UI 显示安全、可操作的中文提示：

- 配置缺失：`CONFIG_MISSING`；
- API Key 缺失：`API_KEY_MISSING`；
- Gateway host permission 缺失：`HOST_PERMISSION_REQUIRED`；
- 401/403：`AUTHENTICATION_FAILED`；
- 404 model not found：`MODEL_NOT_FOUND`；
- 429：`RATE_LIMITED`；
- 超时：`REQUEST_TIMEOUT`；
- 5xx/网络错误：`GATEWAY_UNAVAILABLE`；
- malformed chunk：`STREAM_PROTOCOL_ERROR`。

预期：错误提示不回显 Secret、响应正文或自定义 header；可重试错误提供清晰恢复路径。

## 6. Service Worker 中断

1. 发起长流式响应。
2. 在 `chrome://extensions` 点击扩展 Service Worker 的“停止”，或触发其重启。
3. 重新打开 Side Panel；等待启动 reconciliation。

预期：不承诺断点续传。超过阈值的 `streaming` assistant message 被标记为 `STREAM_INTERRUPTED`，提示后台重启导致中断并允许重试。

2. 在设置 →“通用”→“快捷方式”中，把“快捷方式 2”换成“您的技能”里的某个技能，把“快捷方式 4”改为“不显示”。
3. 回到侧边栏，无需重开即可看到按钮变为：总结、该技能、翻译。点击该技能按钮，确认直接以该技能发送，用户消息顶部显示 `/名称`。
4. 在“您的技能”中删除该技能，确认侧边栏和设置中对应的快捷方式自动消失。
5. 点“恢复默认”，确认恢复为 4 个快捷操作。

6. 在网页上选中一段文字，确认输入框上方出现“选中文本”，且未添加“当前页”。点“翻译”，确认只翻译选中的文字，用户消息来源只显示“选中文本”。移除选中文本后再点“总结”，确认会带上整个页面。
7. 在对话进行中（已有消息、左下角按钮不再显示）点输入框左侧“+”→“快捷方式”，确认子菜单列出与设置一致的快捷方式，鼠标悬停显示 TIPS；点“翻译”，确认效果与新会话页的按钮一致。点“管理快捷方式”，确认打开设置页。生成回复期间，子菜单中的快捷方式为禁用状态。

### 输入框 AI 写作助手

1. 在侧边栏输入框中输入一段草稿，点左侧“+”，确认“快捷方式”和“技能”之间有“AI 写作助手”。
2. 点“AI 写作助手”，确认弹出对话框，多行“原文”输入框已带入当前草稿，可用 Shift+Enter 换行。
3. 确认语气下拉框右侧同一行有模型下拉框（两者都不显示上方标题），默认是当前对话的模型（不在可用列表时显示“Gateway 默认”）；选择语气和另一个模型、填写“语境或要求”，点“开始润色”，确认用所选模型润色，确认显示“正在润色…”，完成后出现“润色结果”。
   - 打开模型下拉框：确认菜单完整显示、不会被对话框底部裁掉（下方空间不够时向上弹出）；顶部“搜索模型”框自动聚焦，输入关键字可过滤（不区分大小写），无结果时显示“没有匹配的模型”；↑/↓ + Enter 可选择；Esc 只关闭菜单、不关闭对话框；菜单打开时滚动对话框或调整侧边栏宽度，菜单自动关闭。
4. 点“复制”确认剪贴板内容为结果；点“填入输入框”，确认对话框关闭，聊天输入框内容替换为润色结果且未自动发送。
   - 网页多行输入框里的 AI 写作助手浮层：分别打开语气和模型下拉框，确认菜单紧贴触发框下方弹出、可以超出浮层底边显示而不被裁掉（窗口下方空间不足时向上弹出）；在模型列表上滚动鼠标滚轮只滚动列表，浮层内容不动；拖动浮层或滚动页面时菜单跟随触发框。
5. 清空原文后点“开始润色”，确认提示“请先在文本框中输入需要润色的文字。”；未配置 Gateway 时确认显示对应错误。按 Esc 或点遮罩可关闭。
